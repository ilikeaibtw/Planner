- [e2ee stage 1 done] New crypto.js (WebCrypto only, no libraries): PBKDF2-SHA256 600,000 iterations with a 16-byte random salt deriving a non-extractable AES-GCM-256 key; encrypt() makes a fresh 12-byte random IV per call and returns the envelope {v:1,alg:"AES-GCM",kdf:"PBKDF2-SHA256",iter,salt(b64),iv(b64),ct(b64)}; decrypt() relies on GCM's built-in auth tag to reject a wrong passphrase or tampered ciphertext (caller must treat any rejection as "don't overwrite remote"); isEnvelope() distinguishes the new envelope shape from a legacy plaintext planner_state row. Optional IndexedDB-backed rememberKey/getRememberedKey/forgetKey store only the non-extractable CryptoKey (never the passphrase), no-op safely where indexedDB is unavailable (e.g. node). Node-tested (module.exports like sync.js): round-trip, wrong-passphrase failure, tampered-ciphertext failure, legacy detection, fresh-IV-per-call, and confirmed sync.js's mergeState still works standalone — all pass. | next: wire crypto into the sync pull/merge/push flow and add the passphrase UI in Settings (stage 2)

- [e2ee stage 2 done] Sync flow rewritten: pull raw remote column -> decryptRemote() (passes legacy plaintext through unchanged, requires cryptoKey and rejects with a tagged error for an envelope, rejects "wrong-passphrase" on GCM auth failure) -> mergeState (sync.js, unchanged) -> save locally + render -> encrypt with the in-memory key -> upsert the ciphertext envelope. A decrypt failure throws before the push step is reached, so the remote blob is never touched on a wrong passphrase. schedulePush()/syncNow() both refuse to run without cryptoKey (status "Locked — enter passphrase").
