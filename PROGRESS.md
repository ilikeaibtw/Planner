- [warm-white backgrounds done] Added 8 premium light presets (Ivory, Cream, Eggshell, Alabaster, Bone, Parchment, Linen, Porcelain) grouped after the original 8, each a subtle warm gradient with faint SVG paper-grain and soft vignette; each preset now carries a tone:'light'|'dark' flag. When Theme is Auto, the app follows the selected preset's tone (explicit Light/Dark still overrides); light tone switches to dark-ink text, frosted ivory cards with fine hairline borders and warm soft shadows, and rebalances the dim overlay to a warm-white wash instead of a black one so light backgrounds stay bright. Added Ink (#111111) and Graphite (#2b2b2b) accent presets; button/checkmark foreground color is now computed from accent luminance (--accent-fg) instead of hardcoded white, so black accents get white text and any future light accent stays readable. Old saved settings (string background keys, no tone field) load unchanged. Verified in-browser: Ivory + Ink + Auto theme renders legible black-on-ivory day view.
- [end-date toggle fix done] Root cause: the End date field had no explicit "has end date" state — `openRoutineModal` set it to `""` for new/no-end routines, but the bare native date input gave users no clear signal of empty-vs-set, so it read as always pre-filled. Added an iOS-style "Set end date" toggle (accent-colored, `--accent-fg`, 200ms transition, respects prefers-reduced-motion) next to the End date label. Off (default for new routines): input disabled, dimmed (opacity 0.4 + slight blur), placeholder "No end date", saves endDate as null. On: input enabled, prefilled with start date + 1 month if empty, and focused; save validates end >= start inline (no alert()). Editing a routine sets the toggle from `routine.endDate`; toggling off and saving clears it. Verified in-browser: new-routine modal shows dimmed/disabled field by default, toggling on prefills+focuses, save persists the end date, reopening via edit reflects it, toggling off and re-saving removes it (confirmed on reopen). Test routine was created and deleted in the browser's isolated data: context, which has localStorage disabled, so the user's real planner.v1 data was never touched.
